| 02-review-iter3 | **WR-01 — slot identity is not injective.** `Slot.slot_key` is `f"{time_slot}\|{seat_type or '-'}"`, a lossy join of two payload-derived fields, and `make_event_id` joins five unescaped payload-derived components with `:`. Two distinct openings can therefore share one Redis hash field, one `SlotRecord` and one `event_id` — and the second is then deduped away by Phase 4's Layer-2 key and never notified. Reproductions (both pinned as executable tests in `tests/unit/test_slot_key_collisions.py`): `Slot(time_slot="19:00\|bar", seat_type=None)` and `Slot(time_slot="19:00", seat_type="bar\|-")` both render `slot_key == "19:00\|bar\|-"`; and `make_event_id("opentable", 42, "2026-05-01", 2, "19:00\|bar", pid) == make_event_id("opentable", 42, "2026-05-01:2", 19, "00\|bar", pid)` because `date`, `party_size` and `slot_key` are three ADJACENT unescaped components. Fix: percent-escape at the point each composite is built — `quote(self.time_slot, safe="")` in `Slot.slot_key` and every component of `make_event_id`. | Not a code-only change. That is a planned change with its own verification, not a review fix folded into iteration 3. The false safety claim that used to sit on `make_event_id` is corrected and the collisions are now executable tests, so the constraint cannot drift back into comforting prose while this waits. |
| 02-review-iter3 | **WR-05 — the poller's `gather` leaks a live sibling task.** `run_until_signal(asyncio.gather(poll_loop(...), reaper_loop(...)))` in `services/poller/main.py:97-112`. `asyncio.gather` without `return_exceptions=True` completes as soon as one child raises and does **not** cancel the other; `run_until_signal`'s `runner.done()` branch then re-raises immediately, so the `finally`'s `if not runner.done(): runner.cancel()` is skipped. Reproduction: make `poll_loop` raise, and `reaper_loop` is still running when `main.py`'s `finally` executes `await producer.stop()` and `await r.aclose()` — the reaper then issues Lua calls against a closed Redis and its exception is never retrieved. Fix: `async with asyncio.TaskGroup() as tg:` wrapping the two `create_task` calls (3.11+), passed to `run_until_signal` as one coroutine, so a failing child cancels its sibling. | Touches the poller's shutdown path, which Phase 1 owns and which `tests/unit/test_graceful_shutdown.py` and the e2e/chaos integration tests all exercise. A `TaskGroup` changes the exception type the caller sees (`ExceptionGroup`), so `run_until_signal`'s re-raise contract, the six shutdown tests and both entry points need re-verifying together. Out of scope for a review-fix pass whose remit was the state machine; the failure only occurs when a poller loop crashes outright, at which point the process is going down anyway. |
