# Phase 6 — UI Design Contract

> Visual and interaction contract for the `web/` Next.js 15 PWA. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Every token below is prescriptive. The executor implements these values verbatim; the auditor compares the built UI against them.
> Scope: FE-01..FE-07 and the *presentation* of PATTERN-01..03. Backend computation of the pattern model is governed by CONTEXT D-105..D-108, not by this file.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled primitives) |
| Preset | not applicable |
| Component library | none — no Radix, no Base UI, no headless-UI dependency |
| Icon library | none — inline SVG only, authored in `src/components/icons/` |
| Font | Inter Variable, self-hosted via `next/font/google` |
| Styling | Tailwind CSS v4, tokens declared in `src/app/globals.css` |
| Theming | light + dark via `prefers-color-scheme` only — no theme toggle, no `localStorage` theme, no `class="dark"` |

**Why no component library.** Locked by CONTEXT **D-109** ("No UI component library; small hand-rolled primitives (`Button`, `Card`, `Field`, `Badge`, `Toast`) with tokens in `globals.css`"). The shadcn initialization gate is therefore answered **N** by an existing upstream decision, not by a question. Consequences accepted: this phase owns its own focus management, dialog semantics, and toast live-region wiring — each is specified explicitly in `## Accessibility Contract` so the executor is not left to improvise.

**Why Inter Variable.** One variable font is required by D-109. Inter is chosen over a warmer humanist face (Figtree, Manrope) for one concrete engineering reason: this UI is numerically dense — a 168-cell heatmap with hour axis labels, confidence-interval percentages, event counts, and slot times — and Inter ships reliable `tnum` (tabular figures) plus `cv05`/`ss01` alternates that keep `1`, `l`, and `I` distinguishable at 14px. Warmth is carried by the palette (warm off-white ground, terracotta accent), not by the typeface. Loaded with `display: 'swap'`, `subsets: ['latin']`, `variable: '--font-sans'`, self-hosted by `next/font` so there is zero third-party font request and zero font-swap CLS against the LCP budget in D-111.

**Token wiring (Tailwind v4).** Declare raw values as CSS custom properties on `:root`, switch them inside `@media (prefers-color-scheme: dark)`, and map them into Tailwind's theme by reference so a single utility class resolves correctly in both schemes:

```css
:root { --ink: #1C1A17; /* …all raw tokens… */ }
@media (prefers-color-scheme: dark) { :root { --ink: #F2EEE8; /* …dark overrides… */ } }
@theme inline { --color-ink: var(--ink); /* …map every token… */ }
```

`@theme inline` (not plain `@theme`) is required — plain `@theme` inlines the value at build time and the media-query override is silently dropped.

## Spacing Scale

4-point base. Tailwind v4's default `--spacing: 0.25rem` is kept, so `p-4` = 16px and `min-h-11` = 44px with no config change.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon-to-label gap, badge inner padding, chip gap |
| sm | 8px | `2` | Compact stacking (label→input, badge row), FeedRow inner gap |
| md | 16px | `4` | Default element spacing, card padding on mobile, page gutter |
| lg | 24px | `6` | Card padding ≥ 640px, gap between cards, form field group spacing |
| xl | 32px | `8` | Layout gaps, spacing between page sections on mobile |
| 2xl | 48px | `12` | Major section breaks on `/` (hero → how-it-works → heatmap → feed) |
| 3xl | 64px | `16` | Page top/bottom padding ≥ 768px, hero vertical rhythm |

**Layout constants**

| Constant | Value | Source |
|----------|-------|--------|
| Content max width | 72rem (1152px) | D-111 |
| Prose max width (pattern summary, how-it-works, legal) | 65ch | readability; narrower than content width by design |
| Page gutter | 16px < 640px, 24px ≥ 640px, 32px ≥ 1024px | mobile-first per D-111 |
| Single-column breakpoint | ≤ 640px (Tailwind `sm`) | D-111 |
| Minimum tap target | 44 × 44px (`min-h-11 min-w-11`) on **every** interactive element | FE-07, D-111 |
| Minimum gap between adjacent tap targets | 8px | prevents 44px targets from being adjacent-but-mistappable |

**Exceptions (the complete list — anything else off-scale is a defect):**

1. **44px tap targets** — 44 is a multiple of 4, so this is on-scale; called out only because it is a hard floor, not a default.
2. **Heatmap internals are unitless SVG viewBox coordinates, not spacing tokens.** The `Heatmap` renders a `viewBox="0 0 {W} {H}"` with `width="100%"` and scales to its container. Internal geometry: cell 16×16 units, 2-unit gap, 2-unit corner radius, 34-unit left gutter for day labels, 18-unit bottom gutter for hour labels. These never appear as CSS pixel values and are exempt from the 4-point scale.
3. **1px hairline borders and 2px focus rings.** Sub-4px by necessity.
4. **Toast stack offset** — 16px from the viewport edge, plus `env(safe-area-inset-bottom)` on iOS standalone. The safe-area inset is device-derived and not a token.

## Typography

Exactly 4 sizes, exactly 2 weights.

| Role | Size | Weight | Line Height | Letter-spacing | Usage |
|------|------|--------|-------------|----------------|-------|
| Body | 16px (`text-base`) | 400 | 1.5 | 0 | Paragraphs, pattern summary prose, form values, feed rows, table cells |
| Label | 14px (`text-sm`) | 600 | 1.4 | 0.005em | Field labels, badges, chips, button text, legend text, metadata lines, table headers |
| Heading | 20px (`text-xl`) | 600 | 1.25 | -0.01em | Card titles, section headings, restaurant name on `/restaurant/[slug]`, step titles |
| Display | 32px (`text-[2rem]`) → 44px ≥ 768px | 600 | 1.15 | -0.02em | Home hero headline only. One per page, and only on `/`. |

- **Weights: 400 and 600 only.** No 500, no 700, no italics anywhere. Emphasis is achieved with weight 600 or with color, never with a third weight.
- **Body is never rendered below 16px.** 14px is reserved for the Label role (short, non-prose strings). Long-form reading text at 14px is a defect.
- **Tabular figures are mandatory** on: heatmap axis labels, event counts, confidence-interval percentages, party size, slot times, notification-history timestamps, and the social-proof counter. Apply `font-variant-numeric: tabular-nums` via a `.tnum` utility. Prevents digit-width jitter as the live counter and feed update.
- **Display scales with a hard breakpoint, not `clamp()`** — `clamp()` produces a fractional font-size that changes during the LCP measurement window on some mobile viewports; a discrete `md:` step does not.

**Exception (the only one):** SVG heatmap axis micro-labels render at **11px, weight 600** inside the `<svg>`. Justification: 24 hour-columns must fit a 288px content width. These labels are *redundant* — every cell's `aria-label` and the CSS tooltip both name the day and hour in full, so the 11px text carries no information that is only available at 11px. Hour labels render every 3rd hour (12a, 3a, 6a, 9a, 12p, 3p, 6p, 9p) rather than all 24.

### Accent reserved for (the complete, closed list)

Accent (`--accent` fill / `--accent-strong` text) appears **only** on:

1. **The single primary button on a screen** — at most one per viewport: "Add to watchlist" (`/restaurant/[slug]`), "Start watching" (home hero), "Continue" then "Create watch" (`/watch/[slug]` steps 1 and 2), "Take me there" (`/go/[token]` available state), "Keep watching" (`/go/[token]` gone state).
2. **The `:focus-visible` ring**, on every focusable element.
3. **Heatmap ramp steps 4 and 5** (the two most-active buckets) and the corresponding legend swatches.
4. **The live-feed status dot** next to the "Live" label on `/`.
5. **Inline text links inside prose** — accent text, always underlined, never accent-on-accent.

### Semantic colors beyond accent

Exactly one: `--danger`, and it is used **only** for the delete-watch destructive path (confirm-dialog primary button, the destructive text in that dialog) and for form/API error text. Notification-outcome badges do **not** get their own hues — see `Badge` in the component inventory.

## Heatmap Color Scale

5-step sequential ramp + one texturally-distinct sparse treatment. Locked by D-114 (5-step sequential, sparse gray) and D-107 (server flags `sparse` when `count < 10`).

### Sequential ramp

| Step | Range (share of `max`) | Light | Dark |
|------|------------------------|-------|------|
| 1 | > 0 … ≤ 20% | `#F7DCCB` | `#3E2A1D` |
| 2 | > 20% … ≤ 40% | `#F0BC9E` | `#633823` |
| 3 | > 40% … ≤ 60% | `#E29268` | `#8F4A29` |
| 4 | > 60% … ≤ 80% | `#C8603C` | `#C4653D` |
| 5 | > 80% … ≤ 100% | `#99331C` | `#F2966F` |

Bucketing is a pure function `bucket(count, max) → 1..5`, unit-tested per D-118. `max` comes from the API payload (D-107), never recomputed client-side.

**Verified properties** (both schemes):
- Relative luminance is strictly monotonic across steps — the ramp reads as intensity in grayscale and for every color-vision profile.
- Every adjacent pair is ≥ **1.30:1** (light: 1.30 / 1.45 / 1.65 / 1.83; dark: 1.36 / 1.50 / 1.66 / 1.78) — no two steps collapse visually.
- Step 1 is ≥ **1.27:1** against the card it sits on, so the lowest non-sparse bucket is never invisible.

### Sparse cells (`count < 10`, flagged server-side)

| Property | Light | Dark |
|----------|-------|------|
| Fill | `#D8D4CC` | `#35312A` |
| Hatch stroke | `#766F64` (**3.4:1** on fill) | `#948C7F` (**3.9:1** on fill) |

Sparse cells are filled with a neutral gray **and** overlaid with a shared `<pattern id="sparse-hatch">` — 45° diagonal lines, 1 unit wide, 4-unit pitch, in the hatch stroke color. The hatch is what makes `sparse` unambiguous: measured against the ramp, the gray alone sits within 1.15:1 of steps 1–2, so lightness cannot carry this distinction (see A-4). One `<pattern>` is defined once in `<defs>` and referenced by every sparse cell.

`sparse` is a *category*, not a low value — a cell with 9 observations and a cell with 0 both render sparse, and both say so in their `aria-label`.

### Cell geometry and grid

- Cell hairline stroke: `#BDB4A4` light / `#4A443B` dark, 0.75 units. Verified ≥ 1.39:1 against every fill including sparse, so the grid structure survives at both ends of the ramp.
- Corner radius 2 viewBox units; 2-unit gap between cells.
- x = hour 0–23 (America/New_York), y = Sunday…Saturday top-to-bottom, matching `day_of_week` 0=Sun (Phase 2 schema).

### Legend

Rendered below the grid, `Label` type, `--ink-muted`. Six entries in order: the five ramp swatches labelled with their **numeric** ranges derived from `max` (e.g. "1–4", "5–9", "10–14", "15–19", "20+"), then the hatched sparse swatch labelled **"fewer than 10 observations"**. Numeric ranges are the non-color channel that keeps the chart WCAG 1.4.1-compliant; a legend of unlabeled swatches is a defect.

## Radii & Elevation

| Token | Value | Applied to |
|-------|-------|-----------|
| `--radius-sm` | 6px | Badges, chips, inputs, heatmap legend swatches, skeleton blocks |
| `--radius-md` | 10px | Buttons, form fields, FeedRow, table containers |
| `--radius-lg` | 16px | Card, PatternCard, WatchCard, dialog, toast |
| `--radius-full` | 9999px | Live dot, StepIndicator markers, avatar-less circular counters |

Elevation is deliberately shallow — this is a content UI, not a layered app shell. **Two levels only:**

| Level | Light | Dark |
|-------|-------|------|
| `--shadow-card` | `0 1px 2px rgb(28 26 23 / 0.06), 0 1px 1px rgb(28 26 23 / 0.04)` | none — use `border: 1px solid var(--border)` instead |
| `--shadow-overlay` | `0 8px 24px rgb(28 26 23 / 0.12), 0 2px 6px rgb(28 26 23 / 0.08)` | `0 8px 24px rgb(0 0 0 / 0.5)` **plus** `border: 1px solid var(--border-strong)` |

Shadows are near-invisible on a `#14120F` ground, so **dark mode expresses elevation with borders, not shadows**. Cards in dark mode always carry a 1px `--border`. Nothing in this phase uses a third elevation level; if a surface seems to need one, it should be a `--surface-sunken` region instead.

## Motion

| Token | Duration | Easing | Applied to |
|-------|----------|--------|-----------|
| `--motion-fast` | 120ms | `cubic-bezier(0.2, 0, 0, 1)` | Hover/active/focus color and border transitions, checkbox and chip toggles |
| `--motion-base` | 200ms | `cubic-bezier(0.2, 0, 0, 1)` | Toast enter/exit, dialog fade, step transition, skeleton→content crossfade |
| `--motion-feed` | 320ms | `cubic-bezier(0.2, 0, 0, 1)` | New FeedRow insert (opacity 0→1, translateY 8px→0) |

Rules:
- **Nothing animates layout-affecting properties.** Only `opacity`, `transform`, `background-color`, `border-color`, `color`. No animated `height`, `width`, `top`, or `margin`. This protects both CLS and the LCP budget.
- **No entrance animation above the fold on `/`.** The hero is static; the LCP element never fades in.
- **The live dot** pulses with a 2s `opacity` keyframe (1 → 0.4 → 1). It is the only looping animation in the app.
- **Skeletons do not shimmer.** A static `--skeleton` fill; a moving gradient is a looping animation that would need its own reduced-motion branch and buys nothing.

### Reduced motion

A single global block, plus two component-specific behaviors:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

1. **Live dot** — stops pulsing and renders as a solid accent dot. It still communicates "live" through the adjacent "Live" text label, which is present in both modes.
2. **FeedRow insert** — no translate, no fade; the row simply appears. Rows still arrive at the same 1/s cap; reduced motion suppresses *animation*, never *information*.

`prefers-reduced-motion` is honored via CSS media queries only — no `matchMedia` in JS, so it works in the server-rendered output with no hydration flash.

## Component Inventory

Twelve components. All live under `src/components/`; primitives in `src/components/ui/`, domain components in `src/components/`. Every component is a server component unless marked **client island**.

### 1. `Button`
- **Variants:** `primary` (accent fill, white/`--accent-ink` text — max one per viewport), `secondary` (`--surface-raised` fill, `--border-strong` 1px border, `--ink` text), `ghost` (transparent, `--ink` text, `--surface-sunken` hover), `destructive` (`--danger` fill — used only in the delete confirmation dialog).
- **Sizes:** `md` (h 44px, px 16, Label type) and `lg` (h 52px, px 24, Label type) — no `sm`; a button smaller than 44px violates FE-07.
- **States:** rest, hover (accent → `--accent-strong`; secondary/ghost → `--surface-sunken`), `:focus-visible` (2px `--ring` outline, 2px offset), active (no transform — `translateY` on tap causes jitter on iOS), disabled (`--surface-sunken` fill, `--ink-disabled` text, `cursor: not-allowed`, `aria-disabled` **not** the `disabled` attribute when the button must stay focusable for a tooltip), **pending** (label replaced by the label + an inline 16px spinner, `aria-busy="true"`, width locked to the rest-state width so the layout does not jump).
- **A11y:** real `<button>` or `<a>`; never a `<div>` with a click handler. Icon-only buttons carry `aria-label`.

### 2. `Card`
- Slots: optional `header` (Heading type + optional trailing `Badge`), `body`, optional `footer`.
- `--surface-raised` fill, `--radius-lg`, `--shadow-card` (light) / 1px `--border` (dark and light both carry the border; the shadow is additive in light).
- Padding: 16px < 640px, 24px ≥ 640px.
- Not interactive by default. A whole-card link (WatchCard, search result) uses a single `<a>` covering the title with a `::after` overlay so the card is one tab stop, not several.

### 3. `Field`
- Composes: `<label>` (Label type, `--ink`) → optional helper text (Label type, `--ink-muted`) → control → error slot.
- Control heights 44px; `--radius-md`; 1px `--border-strong`; `--surface-raised` fill; 12px horizontal padding.
- **States:** rest, focus (2px `--ring` outline + 2px offset — the border does not change color, so a focused-and-invalid field still reads as invalid), invalid (`--danger` 1px border + error text), disabled (`--surface-sunken`, `--ink-disabled`).
- **Error slot is always present in the DOM** (empty, zero height) so validation does not shift layout.
- **A11y:** `<label for>` always — never placeholder-as-label. Errors are `role="alert"` and wired via `aria-describedby`; the field carries `aria-invalid="true"`.
- **Sub-controls used in this phase:** party-size stepper (two 44×44 `−`/`+` buttons flanking a `readonly` numeric display; the display is an `<input type="number">` so keyboard and screen-reader users can type a value directly, with `aria-live="polite"` on the value), date inputs, time-window selects, days-of-week chip group (`role="group"`, each chip a `<button aria-pressed>` at 44px min), seat-type radio group, email/phone text inputs (`inputmode="email"` / `inputmode="tel"`, `autocomplete="email"` / `"tel"`).

### 4. `Badge`
- Neutral by default: `--surface-sunken` fill, `--ink` text, Label type, `--radius-sm`, 4px/8px padding, 24px height.
- **Variants:** `neutral` (default — used for cuisine, price tier, `active_watch_count`, and every notification outcome), `accent-outline` (1px `--accent` border, transparent fill, `--accent-strong` text — used **only** for the "Sample data" label on the home sample heatmap), `hatched` (legend swatch for sparse).
- **Notification outcomes do not get unique hues.** `sent`, `delivered`, `clicked`, `still available`, and `gone` all render as neutral badges differentiated by their **text** plus a 12px inline SVG glyph (check for delivered/clicked/still-available, slash for gone). This is deliberate: five semantic colors would blow the accent budget and make color the only channel. Outcome is always readable as text.

### 5. `Toast` — **client island**
- Bottom-anchored on mobile (16px + `env(safe-area-inset-bottom)`), bottom-right ≥ 640px. Max width 400px. `--surface-raised`, `--radius-lg`, `--shadow-overlay`, 1px `--border-strong`.
- Content: message (Body type) + optional single action button (`ghost`, 44px) + dismiss button (44×44, `aria-label="Dismiss"`).
- Auto-dismiss at 6s **only** when there is no action; a toast with an action ("Undo") persists until dismissed. Auto-dismiss timer pauses on hover and on focus-within.
- Max 3 stacked; the oldest is removed first.
- **A11y:** a single persistent `<div role="status" aria-live="polite" aria-atomic="false">` region in the root layout that toasts are portaled into. Rollback/error toasts use `role="alert"` (assertive). A toast is never the only place an error appears (A-7).
- **Used in this phase for:** optimistic-mutation rollback on `/manage/t/[token]` (D-115), offline-queued-submission confirmation on `/watch/[slug]` (D-113), and push-subscription success.

### 6. `Heatmap`
- **Server-rendered SVG. No chart library, no client JS** (D-114). Signature: `({ cells, max, days, hours, windowDays, sample? })` fed directly by the D-107 payload.
- `viewBox="0 0 {34 + 24*18} {18 + 7*18}"`, `width="100%"`, `height="auto"`, `preserveAspectRatio="xMidYMid meet"`.
- Day labels (S M T W T F S) in the 34-unit left gutter; hour labels every 3rd hour in the 18-unit bottom gutter; both at 11px weight 600, `--ink-muted`.
- Ramp, sparse hatch, hairlines, and legend exactly as specified in `## Heatmap Color Scale`.
- **Tooltip:** CSS/SVG-only. Each cell is a `<g tabindex="-1">` containing `<rect>` + a `<title>`; a sibling `<g class="tip">` is `opacity: 0` and becomes `opacity: 1` on `:hover` and on `:focus-visible` of the parent group. Tip text: `Fri 8 PM · 12 openings` or `Fri 8 PM · not enough data`. Tips near the right edge anchor with `text-anchor="end"` (a static, index-derived choice — no runtime measurement).
- **`sample` prop** renders the `accent-outline` "Sample data" badge above the grid and prefixes the container `aria-label` with "Sample data — ". Required by the D-112 home-page sample heatmap and the CONTEXT specific-idea "nobody mistakes it for live data".
- A11y: see `## Accessibility Contract`.

### 7. `FeedRow`
- Single row: live dot column (16px, only on the newest row) · text · timestamp.
- Text: Body type. `Just now: Table for 2 at Carbone — Fri 8:00 PM`.
- Restaurant name truncates to one line with ellipsis and carries the full name in `title`; the longest seeded name is 20 characters ("Mission Chinese Food"), so truncation is an overflow backstop rather than the common case.
- Rows are `<li>` inside a single `<ol>`; height is fixed at 56px so appends never shift the section below.
- Enter animation per `--motion-feed`; suppressed under reduced motion.

### 8. `WatchCard`
- Used on `/manage/t/[token]`. Header: restaurant name (Heading) + status `Badge` (`Active` / `Paused`). Body: party size, date range, time window, days-of-week, channels — each a Label-type key with a Body-type value. Footer: `Pause`/`Resume` toggle, `Edit`, `Delete` — three 44px `ghost` buttons, 8px apart.
- **Paused state:** the card body drops to `--ink-muted` and the status badge reads `Paused`. Opacity is **not** used to convey paused state (it would push text below 4.5:1).
- Expanding `Edit` renders the step-1 `Field` set inline beneath the card body — no modal, no route change (D-115).

### 9. `StepIndicator`
- Two steps: `Preferences` → `Contact`. Rendered as `<ol>` with a 24px circular marker per step + Label-type title.
- Marker states: complete (accent fill + white check glyph), current (accent fill + white numeral, plus a 2px accent ring at 3px offset), upcoming (`--surface-sunken` fill, `--ink-muted` numeral).
- **A11y:** the container has `aria-label="Watch setup progress"`; the current step carries `aria-current="step"`; completed steps include visually-hidden text " (completed)". Never conveys progress by color alone.

### 10. `PatternCard`
- Two mutually exclusive renderings driven by `status` from D-108:
  - **`ready`** — `summary_text` as Body prose at 65ch max, followed by per-rule chips. Each chip is a neutral `Badge` with its rule name and, beneath it in Label/`--ink-muted`, the CI text: `36% of 84 openings · 95% CI 28–44%`.
  - **`collecting_data`** — the placeholder from `## Copywriting Contract`, plus a thin progress hairline showing days-of-history against 14. No chips, no partial summary, no grayed-out fake pattern.
- The card **never** renders a rule that the model did not detect, in any visual treatment (not grayed, not "not detected", not a zero-state chip). Omission is the contract (D-106).

### 11. `EmptyState`
- Centered stack: optional 32px inline SVG glyph (`--ink-muted`) · Heading · Body (`--ink-muted`, 45ch max) · optional single action `Button` (`secondary`).
- 32px vertical padding, never a fixed height — it sizes to content so a short empty state does not leave a dead zone.
- Every empty state in this phase names a **next action or a next expectation** — never a bare "No data".

### 12. `OfflineState`
- Same shape as `EmptyState`, different semantics and copy, with a `Retry` `Button` (`secondary`) and a `--surface-sunken` background band so it reads as a system condition rather than as content.
- **Two distinct causes with distinct copy** (see `## State Contracts`): device offline (`navigator.onLine === false` or a service-worker cache miss) vs. backend unreachable while the device is online (fetch failure / 5xx). Collapsing these into one message is a defect — the user's remedy is different in each case.

### Live feed row format

`{relative time}: Table for {n} at {Restaurant} — {Ddd h:mm A}`

- Relative time: `Just now` (< 60s) · `{n} min ago` (1–59 min) · `{n} hr ago` (≥ 60 min).
- Slot time in America/New_York, 12-hour with minutes and uppercase meridiem: `Fri 8:00 PM`.
- Party size always renders as `Table for 1` / `Table for 2` — the noun never pluralizes ("Tables for 2" is a defect).
- Example: `Just now: Table for 2 at Carbone — Fri 8:00 PM`

### Pattern sentence rules (PATTERN-01/02, the "never over-claim" contract)

The frontend renders `summary_text` from the API verbatim. These rules constrain both that server-generated string and any UI text around it. They are the honesty contract for the whole product and are the highest-risk copy in the phase.

**Required:**
1. Only rules the model actually detected appear. An undetected rule is **omitted**, never hedged, never grayed out, never shown as "not detected".
2. Every claim carries its sample size and its confidence interval: `36% of 84 openings · 95% CI 28–44%`.
3. Hedged, observational verbs only: "tend to", "most often", "we've seen", "historically". 
4. The window is always stated: "over the last 30 days".
5. Below threshold, the placeholder is exact and quantified: **"Still collecting data — we describe a restaurant's pattern after 14 days of history and 30 openings. We're 6 days in with 12 openings so far."**
6. The estimated-window sentence renders only when the API supplies it: **"estimated window: ~8 minutes based on this restaurant's history"** (PATTERN-03, D-108). When absent, nothing takes its place.
7. The home-page sample heatmap always carries the visible "Sample data" badge and the accessible name prefix "Sample data — ".

**Forbidden anywhere in pattern copy:** "will", "predicts", "prediction", "guaranteed", "always", "never", "best time to book", "secret", "hack", "insider", "beat the system", any countdown implying certainty, and any percentage stated without its `n`.

**Reference sentence (correct form):**
> Over the last 30 days, tables at Carbone have tended to open about 48 hours before service — 36% of the 84 openings we've seen (95% CI 28–44%). Openings cluster around 10 AM, 2 PM, and 5 PM. When a table opens, it stays open for about 6 minutes (median of 41 openings).

## Accessibility Contract

Target: **WCAG 2.1 AA**. Verified by an axe Vitest assertion on every page shell (D-111, D-118) — zero violations is the gate, not a guideline.

### Focus

- `:focus-visible` only — never `:focus`, so mouse clicks don't ring.
- Ring: `outline: 2px solid var(--ring); outline-offset: 2px;` on every focusable element. Measured ≥ 5.3:1 (light) / 7.9:1 (dark) against the surface — comfortably over the 3:1 non-text minimum.
- `outline: none` without a replacement ring is a defect anywhere in the codebase.
- **Focus order follows DOM order on every page.** No positive `tabindex` anywhere.
- **Skip link** — first focusable element in the root layout: "Skip to main content" → `#main`. Visually hidden until focused.
- **Focus return:** closing the delete-confirmation dialog returns focus to the `Delete` button that opened it. Advancing `/watch/[slug]` from step 1 to step 2 moves focus to the step-2 heading (`tabIndex={-1}`), never to the browser default.

### Heatmap (D-114 "keyboard-focusable cells with `aria-label`")

- The `<svg>` carries `role="grid"`, `aria-label="Availability heatmap — openings by day and hour over the last 30 days"` (prefixed "Sample data — " when `sample`), and `aria-describedby` pointing at the legend.
- Each day row is `role="row"`; each cell is `role="gridcell"`.
- **Roving tabindex:** exactly **one** cell is `tabindex="0"` (the highest-count cell, so a keyboard user lands on the most informative cell); all others are `tabindex="-1"`. Arrow keys move focus within the grid; `Home`/`End` jump to row start/end. The whole heatmap is therefore **one** tab stop, not 168 — a 168-stop tab trap in the middle of a page is a worse a11y outcome than the density itself.
- Cell `aria-label`, two forms:
  - `Friday 8 PM — 12 openings`
  - `Friday 3 AM — not enough data, fewer than 10 openings`
- Focused cell renders the standard focus ring **inside** the SVG via `outline` on the `<g>`; the CSS tooltip also opens on `:focus-visible`, so keyboard and pointer users get identical information.
- **Tap targets exempt** under WCAG 2.5.8 "Essential" — recorded as assumption **A-5**, with the PatternCard prose and per-cell labels as the equivalent-information path.

### Live feed (D-112, 1 update/s cap)

- `<ol aria-live="polite" aria-relevant="additions" aria-atomic="false">`.
- The D-112 queue-and-timer rate cap of **1 event/s is an accessibility mechanism as much as a rendering one** — an uncapped `aria-live` region during a burst of cancellations makes a screen reader unusable. The cap must be enforced before the DOM append, not after.
- **`Pause updates` toggle is required** (WCAG 2.2.2 — auto-updating information). 44px, adjacent to the "Live" label, `aria-pressed`. While paused, incoming events accumulate in the queue and the button reads `Resume updates (3 new)`. This was not in CONTEXT; recorded as assumption **A-6**.
- The live dot is decorative (`aria-hidden="true"`); the adjacent text "Live" / "Paused" is the accessible signal.

### Forms

- Every control has a programmatic label. Placeholder is never the label.
- The days-of-week chip group is `role="group"` with an `aria-label`; each chip is `<button aria-pressed>`.
- Error text is `role="alert"`, referenced by `aria-describedby`, and the field carries `aria-invalid="true"`.
- On failed submit, focus moves to the first invalid field.
- The party-size stepper announces its value via `aria-live="polite"` on the value element.
- The notification preview card is `aria-label="Preview of the alert you'll receive"` and is not a live region — it updates as the user types and would otherwise chatter.

### Dialogs

The delete confirmation is the only dialog in the phase. Native `<dialog>` with `showModal()`: `aria-labelledby` the heading, `aria-describedby` the body, focus trapped by the platform, `Esc` closes, focus returns to the trigger. The `Delete watch` button is **not** autofocused — the destructive action is never the default focus.

### Other

- Landmarks on every page: `<header>`, `<nav aria-label="Main">`, `<main id="main">`, `<footer>`.
- Exactly one `<h1>` per page; heading levels never skip.
- `<html lang="en">`.
- Images: `next/image` with meaningful `alt` for cover photos (`"{Restaurant} interior"`) and `alt=""` for decorative ones.
- **Color is never the sole channel:** heatmap intensity is backed by numeric legend ranges and per-cell labels; sparse is backed by hatch texture and label text; notification outcomes are backed by badge text; step progress is backed by `aria-current` and visually-hidden "(completed)".
- Zoom to 200% and to 320px CSS width without horizontal scroll or content loss.
- `prefers-reduced-motion` honored per `## Motion`.
